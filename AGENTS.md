# Repository Instructions

Before working in this repository:

1. Read `working_rule.md` completely as the Human–AI governance charter.
2. Read `.agents/RULES_INDEX.md` completely.
3. Follow every active rule, workflow, and scoped source that the index routes to for the current task.

For work under `total_practice/Practice_1/`, also read:

- `total_practice/Practice_1/README.md`
- `total_practice/Practice_1/docs/rules/architecture_rule.md`
- `total_practice/Practice_1/docs/rules/rule_code.md`
- the relevant approved exercise specification, when it exists
- the approved before-process plan, when implementation is requested

For work under `total_practice/Practice_4/`:

- Follow any Practice 4-specific rules routed by `.agents/RULES_INDEX.md`. Do not invent or duplicate rules that are already defined at repository level.
- Before drafting or revising project documents, read the assignment and inspect existing Practice 4 files. Separate confirmed requirements, proposals, and pending decisions; do not represent an unverified dataset or data contract as approved.
- Read the approved `PROJECT_OVERVIEW.md` and `plan_overview.md` when they exist. If either is absent or still a draft, report its status rather than assuming approval.
- Before implementing a phase, read its approved specification and approved before-process plan, when required by the active workflow. Do not implement from an unapproved draft.
- Work phase by phase: propose and review the phase design, obtain Human approval, implement, validate, and request Human review before moving to the next phase.
- Keep changes scoped to Practice 4 unless the Human explicitly authorizes edits to shared repository instructions or other practice directories.

Historical acknowledgements are not startup instructions and do not need to be read,
signed, or updated by a new agent or session. If instructions conflict, stop, identify
the conflict, explain its impact, and wait for Human resolution before implementing
the disputed action.
